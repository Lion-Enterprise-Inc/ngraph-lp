AIに社内の道具を使わせる共通規格「MCP」が新版に(7/28)——中小企業のツール選びが変わる

2026.07.29 朝 ｜ 株式会社NGraph

2026年7月28日、AIアシスタントに会計ソフトや予約システム、在庫管理といった"外部の道具"を使わせるための共通規格「MCP（Model Context Protocol）」の最終仕様「2026-07-28」が公開されました（一次情報）。結論から言うと、これは中小企業にとって「AI導入の最大の壁＝ツールがつながらない・使われない」が、規格の側から崩れ始めたという話です。MCPとは、ひとことで言えば「AIと社内の道具をつなぐ共通コンセントの規格」のことです。

何が起きたか

MCP（Model Context Protocol）は、ChatGPTやClaudeといったAIアシスタントに、自社の会計ソフト・予約システム・在庫データといった"外部の道具"を使わせるための共通規格です。この規格がなければ、道具ごとに個別の接続プログラムを作る必要がありました。

2026年7月28日、その最終仕様「2026-07-28」が公開されました。バージョン名がそのまま公開日という命名です。主な変更点は次の4つです。

  • ステートレス化 — これまで必要だった接続の下準備（initialize/initializedというやり取りやセッションIDヘッダ）が廃止され、1回のリクエストで完結するようになりました。どのサーバーに送っても届くため、特別な構成なしに普通のHTTPインフラで動かせ、増やせます。
  • MCP Apps — ツール側がAIの会話の中に画面（UI）を表示できるようになりました。表示はサンドボックス化されたiframe（隔離された安全な表示枠）内で行われます。
  • Tasks拡張の正式化 — 時間のかかる長い作業を扱う仕組みが、実験的な機能から正式な拡張に格上げされました。
  • 認可の強化 — OAuth 2.0／OpenID Connectという広く使われる認証の仕組みに整合させ、安全面が強化されました。

出典はModel Context Protocol公式ブログ「The 2026-07-28 MCP Specification Release Candidate」です。

なぜ重要か

中小企業のAI導入が「使われない・つながらない」で止まる最大の理由は、AIと現場の道具——POS（レジ）・会計ソフト・予約システム・受発注システム——が個別配線で、都度カスタム開発が必要だったことにあります。共通規格が固まっていくと、この"配線"が部品化していきます。ツールを作る側がMCPに対応すれば、どのAIアシスタントからでも同じ規格でつながる方向に進んでいくということです。

今回の改定でとくに効くのは、ステートレス化です。接続の下準備が要らなくなったことで、普通のサーバーでMCP対応の道具を動かせるようになりました。提供側の実装コストが下がれば、結果的に中小企業が選べるMCP対応ツールの数も増えていく——という波及です。プラットフォーム間の囲い込みの綱引きも、規格が固まるほど一段落しやすくなり、相互接続が前提の世界に近づいていきます。

ただし、ここは盛らずに言っておきます。「規格が固まった」ことと「明日から中小企業のツールが自動でつながる」ことは別です。実際に各ツールがMCPに対応し、現場のデータが整理されて初めて効いてきます。過度な期待は禁物です。

中小企業は何をすべきか

  • 今すぐ何かを買い替える必要はありません。ただし、これから会計ソフト・予約システム・受発注システム・在庫管理などの業務ツールを選ぶときは、ベンダーに「AI連携（MCP対応）の予定はありますか」と一言聞く——これを新しい判断軸に加えてください。
  • 自社の"つながっていないデータ"を棚卸ししておく。Excel管理・紙の台帳・バラバラのシステムに散らばったデータを、将来AIエージェントに渡す「入口」として、今のうちに意識して整理しておく価値があります。
  • 規格の完成を待って導入を止めない。1業務×1ツールで小さく試し、現場がAIに慣れることを優先してください。
NGraphの視点：私たち自身、社内の見積・請求のワークフローをAIに任せて回しています。そこで効いたのは、高機能なAIそのものより「どのデータを・どの順で渡すか」を人間側が設計し、AIの提案を人が確認してから確定する導線を作ったことでした。規格が整うほど、この"渡し方の設計"がボトルネックとして残ります。これは福井の飲食グループ本部（12店舗）の業務のAI化に取り組む中でも同じ実感です。
